# ClipMind v1.3.0

ClipMind turns a video into searchable speech, screen text and timestamped
images that people and AI agents can inspect. This release collects the changes
since `v1.2.0`, makes installation more direct, and replaces the synthetic-only
first impression with evidence from real public talks.

These notes were prepared on 2026-11-16 for publication from `main`. The
[GitHub release](https://github.com/yy31104/clipmind/releases/tag/v1.3.0) is the
authority for the published tag and downloadable artifacts; a workflow or
installation recipe alone does not establish that an image is publicly available.

## What changed since v1.2.0

The acquisition foundation now keeps source identity in adapters, records
ownership before temporary media are written, retries unfinished cleanup on
startup, and remembers successful acquisition strategies by source rather than
sharing a single global winner. Failure selection considers every attempt.
The metadata-probe API bounds work and distinguishes a local budget refusal
from evidence that the source is unavailable.

Bilibili reuse now respects explicit video parts without rewriting stored media
IDs. Repeating the same canonical URL can reuse its own downloader-resolved
result; this does not make unspecified parts, explicit parts, av IDs and BV IDs
universally interchangeable. A temporary Chrome session can acquire Douyin
media when the ordinary ladder fails, with checks against returning another
video and against downloads continuing after cancellation. Live streams are
refused before downloading media. This is not a batch of newly verified social
platforms; the current evidence is in [PLATFORMS.md](../PLATFORMS.md).

Results are easier to read and manage: Library and Inbox support individual and
multiple selection for recoverable removal; cards align; long pages offer a
return-to-top control. Reading previews are separate from the complete retained
frame sequence, which can be opened in full. Compact reading exports remain
distinct from complete Evidence Pack exports. OCR failures are visible, and the
repair utility refuses to replace a pack when refreshed OCR still fails.

Apple Vision compatibility was repaired on current macOS. The Linux synthetic
OCR fixture now places text on a high-contrast background and passes real
Tesseract decoding without weakening its assertions. ASR silence guards and
real Whisper comparisons are documented, including recognition mistakes and
quiet-speech limits. The portable decoder uses an immutable official
faster-whisper fix for empty alignments. Historical failures and the paired
guard results remain in [the benchmark notes](../BENCHMARK.md).

## Try it

With uv, Git and the [system prerequisites](../INSTALL.md) installed:

```bash
uv tool install --python 3.12 git+https://github.com/yy31104/clipmind.git@v1.3.0
```

Run `clipmind doctor`, then `clipmind serve`, and open
[127.0.0.1:8420](http://127.0.0.1:8420). The explicit GitHub source URL avoids
the unrelated PyPI project named `clipmind`; this release does not publish to
PyPI. The tool command resolves the tagged dependency constraints. Development
and container installations instead use the frozen lock.

The release workflow also builds Linux amd64/arm64 images, with source,
revision, version and MCP ownership labels. Once its public pull check passes,
the versioned container command is:

```bash
docker run --rm -p 127.0.0.1:8420:8420 -v clipmind-data:/data ghcr.io/yy31104/clipmind:v1.3.0
```

Python wheels, the source distribution and `SHA256SUMS` are attached by the
release workflow after a clean installation check. Container publication and
anonymous access require their own verification. The image includes FFmpeg
and Tesseract, uses CPU inference by default, and does not include Chrome or
promise native Douyin browser-session behavior. No signed/notarized DMG,
Homebrew cask or hosted service is introduced.

## Real demonstration and measurements

The [new demonstration](../REAL_TALK_DEMO.md) uses the complete 39:24 CC BY 4.0
talk **Xous: A Pure-Rust Rethink of the Embedded Operating System**, by bunnie
and Sean “xobs” Cross. Real URL
acquisition produced 749 transcript segments and 387 retained visual states,
with 10 reading previews. The browser recording searches a spoken phrase and
opens its timestamped slide with nearby speech. A separate actual AI-agent
session calls the MCP search, timeline and frame tools to answer a memory
ownership question with source timestamps. The recorded first search misses
are preserved; these are not simulated successful responses. Acquisition
leftovers were empty after processing.

The [real-talk table](../REAL_TALK_BENCHMARK.md) runs ten distinct English public
talks, 180 seconds each: 30 minutes of source material, not ten complete
long-form talks. All ten samples produced structurally complete speech, OCR
and visual outputs, with no temporary acquisition leftovers. The report
measures informational-change alignment, selected text/code ROI character
errors, and transcription agreement with the publisher's captions. It records
misses and difficult code slides rather than treating completeness as accuracy.

Important limits on those numbers:

- Source-only visual annotations were prepared with AI assistance before
  inspecting outputs; independent human review is still pending.
- Publisher captions were generated with transcribee and are not independently
  human-verified gold transcripts. Agreement with them is not a certified ASR
  accuracy score.
- The ten-sample run uses Apple M4 Pro/24 GB, MLX Whisper and Apple Vision,
  explicitly configured for English. It does not establish identical quality
  or speed for Windows, Linux, other languages or every platform.
- A complete pack means the required artifacts and processing stages finished;
  it does not promise that every word or brief visual change was preserved.

An isolated native installation also processed a separate 12-second source
copy with real local ASR and Vision OCR, exported a complete ZIP, left no
acquisition media and preserved the input bytes. CLI, packaged web assets,
localhost UI and the six MCP tools were checked outside the source checkout.

## Storage and integrations

Temporary source media, extracted audio and sampling files are cleaned through
normal completion, failure, cancellation and restart recovery. Saved Evidence
Packs, exported ZIPs and speech-model weights intentionally remain. The first
ASR run may download model weights; the container keeps them under
`/data/.cache/huggingface` in its named data volume so `--rm` does not redownload
them every time. Removing the container does not delete that volume. Moving
items into Library `.trash` also does not release their disk space.

MCP metadata and a GitHub-authenticated publication workflow are included.
Registry publication and lookup are separate from adding the configuration;
this document does not claim acceptance by a third-party tool directory.
See [MCP publishing](../MCP_PUBLISHING.md), [installation](../INSTALL.md), and
[platform evidence](../PLATFORMS.md) for the exact boundaries.
